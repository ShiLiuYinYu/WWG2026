# 运行流程

## 已实现的入口与地点

```text
Title（Build index 0）
  └─ 开始游戏 → S0 楼外
       └─ 读楼层展板 → S0_Corridor（白天 5F 走廊）
            ├─ S0_ClubRoom（集合、开题、白天调查、23:30 熄灯）
            └─ S0_Bridge（白天 4F 连廊入口，可返回走廊）
       └─ S0_ClubRoom 看掉落照片 → S1（夜间活动室）
            └─ P1 三项对位 → 工牌 → S1_Corridor
                 └─ S1_BridgeEntrance（S1 当前终点，可返回）
```

主菜单「读取存档」读取最近的 S0 手动存档或 S1 阶段检查点；「设置」仍只有占位日志；「退出游戏」在编辑器内停止播放。菜单按钮由 `TitleMenuController.Awake` 绑定，场景中的四个 `Button` 字段必须非空。`TitleMenuWiring` 只在显式执行 `WWG/Wire Title Menu` 时接线；按钮生成工具完成后也会调用接线。域重载不再自动重建按钮。

### 地点切换

1. 热点调用章节控制器的 `HandleHotspot(action)`；控制器先判断剧情阶段和面板状态。
2. 控制器记录章节内状态与目标地点，调用 `GameFlow.LoadLocation()`。目标必须登记在 Build Settings。
3. 新地点的同章控制器在 `Start()` 取出临时快照，恢复 HUD、谜题物件与可点击热点；随后显示需要在到达后出现的对白。
4. S1 在关键进度及地点切换时写入阶段检查点。读档可切回检查点对应地点；照片、工牌及 P1 状态随快照恢复。

临时切屏状态只在同一次 Play 中有效。S0 暂停菜单可手动保存/读取白天调查标记与地点，转场演出中不可存档；S1 的 PlayerPrefs 阶段检查点跨 Play 保留，暂停菜单可手动保存/读取。两者都是章节检查点，尚未包含完整 Demo 所需的所有状态。S2–S4、P2/P3 和完整 Demo 存档仍是设计目标。

### 游戏内 UI

S0/S1 的七个地点场景均安装了 `Gameplay overlay`：顶部显示暂停入口、时间、目标、状态和任务记录；底部显示物品栏。ESC 可开关暂停菜单，暂停时 `Time.timeScale=0`。S1 已取得的旧照片和工牌显示在物品栏，右键或左键打开详情；可选择物品后点击热点，或拖到热点使用。旧照片可对照活动室的窗帘、桌灯与椅子；工牌提供 4F 线索。暂停菜单提供继续、章节检查点存读档、主音量和返回主菜单。共享 UI 的场景安装命令是 `WWG/UI/Install Gameplay Overlay`，已有实例时不会重复创建。

### 编辑与核对

- 场景资源已拆分，日常直接编辑对应地点 `.unity`。`WWG/Build S0 Scene`、`WWG/Build S1 Scene` 和 `WWG/Build Title Scene` 在目标已存在时返回，不覆盖手工资产。
- 一次性拆分命令 `WWG/Setup/Split Location Scenes` 只适用于未拆分的原始 S0/S1；检测到目标场景存在时停止。
- 修改场景流转后从 `Title` 开始 Play，依次点击菜单、楼层展板、大门、活动室、连廊返回、照片、P1、工牌、夜间走廊和 4F 入口。检查 Console，并用包含 Overlay UI 的截图确认按钮和对话框可见。
