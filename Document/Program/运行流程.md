# 运行流程

## 已实现的入口与地点

```text
Title（Build index 0）
  └─ 开始游戏 → S0 楼外
       └─ 进门 → S0_Corridor（白天 5F 走廊，楼外展板可选读）
            ├─ S0_ClubRoom（集合、开题、白天调查、23:30 熄灯）
            └─ S0_Bridge（白天 4F 连廊入口，可返回走廊）
       └─ S0_ClubRoom 看掉落照片 → S1（夜间活动室）
            └─ P1 三项对位 → 工牌 → S1_Corridor
                 └─ S1_BridgeEntrance → BridgeOdd4F（S2，入口调整应急灯）
                      └─ BridgeSpan4F（首次查玻璃选路线）↔ BridgeEven4F（P2 资料柜）
                           └─ 返回 BridgeOdd4F ↔ ClubRoom（5F 安全屋视图）
                                └─ BridgeOdd4F ↓ ServerRoom3F（S3，P3 三项索引 → 录音 → U 盘）
                                     └─ FinaleClubRoom（S4，5F 安全屋 → 白天复盘 → 16:00 第二次选择 → 24H 结尾）
```

主菜单「读取存档」打开三槽位界面，点击存档条直接读取；旧的最近章节检查点首次打开时复制到槽位 1。面板底部另有「读取最近检查点」，用于继续后续自动保存的进度。「设置」仍只有占位日志；「退出游戏」在编辑器内停止播放。菜单按钮由 `TitleMenuController.Awake` 绑定，场景中的四个 `Button` 字段必须非空。`TitleMenuWiring` 只在显式执行 `WWG/Wire Title Menu` 时接线；按钮生成工具完成后也会调用接线。域重载不再自动重建按钮。

### 地点切换

1. 热点调用章节控制器的 `HandleHotspot(action)`；控制器先判断剧情阶段和面板状态。
2. 控制器记录章节内状态与目标地点，调用 `GameFlow.LoadLocation()`。目标必须登记在 Build Settings。
3. 新地点的同章控制器在 `Start()` 取出临时快照，恢复 HUD、谜题物件与可点击热点；随后显示需要在到达后出现的对白。
4. S1 在关键进度及地点切换时写入阶段检查点。读档可切回检查点对应地点；照片、工牌及 P1 状态随快照恢复。

临时切屏状态只在同一次 Play 中有效。S0/S1 保留原章节检查点，S2–S4 使用 `GameState` 并在关键状态变更时写入 `WWG_Save`。玩家手动存读档统一使用三个槽位，每个槽位内部记录章节快照、游戏内时间与保存时间；界面只展示槽位编号及两项时间，不向玩家显示 S_n 阶段名。覆盖和删除需要确认。槽位仍是章节检查点的容器，不是完整 Demo 存档。`WWG/Dev/Play S2`、`Play S3`、`Play S4` 的样本只在本次 Play 内有效，不写玩家存档。

S2 的场景文件为 `S2.unity`、`S2/S2_BridgeSpan4F.unity`、`S2/S2_BridgeEven4F.unity`、`S2/S2_ClubRoom.unity`；S3/S4 入口分别为 `S3.unity`、`S4.unity`。`BridgeOdd4F` 等仍是存档中的逻辑地点 ID，加载时由 `StoryIds.LocationScene(chapterId, locationId)` 映射到阶段场景。

编辑器中直接打开 S2 任一地点场景或 S3/S4 场景按 Play，若没有上章交接或开发菜单传入的状态，就使用 `ChapterPreviewStates` 的内存默认配置。S2 的默认地点随当前场景变化；偶数栋已确认开灯路线，安全屋已取得 P2 任务物。预览期间不写玩家检查点或槽位；构建版仍需要正式交接或有效存档。

### 对白

1. 章节控制器在进入地点或点击热点时调用 `DialogueService.Ensure()` 和 `Play(nodeId, context, once)`；对白文本由 `Assets/Yarn/` 编译进 `WWG.yarnproject`。
2. 首次播放时 `WwgDialogueHost` 从 `Resources/Dialogue` 实例化并常驻；后续地点复用同一个 `DialogueRunner`。全屏点击推进，`show_info` 阻塞到信息面板关闭，`show_photo` 阻塞到照片面板关闭。
3. Yarn 命令只修改章节状态、打开文档或请求转场；P1/P2、场景加载和章节检查点仍由控制器执行。一次性冲击用 `apply_shock` 的 flag 幂等保护。
4. 对话进行中暂停、物品详情和存档入口禁用；章节计时器暂停。对话结束后章节控制器在自己的完成事件里保存检查点或执行排队的转场。
5. 修改 `.yarn` 后执行 `WWG/Yarn/Validate Dialogue` 检查节点、行 ID、命令和文档引用。

S2 在单数栋 4F 入口切换应急灯。首次点击中段右侧玻璃时按当时的灯光记录 `RouteLight` 或 `RouteDark` 并保存。两条路线都实地核对近端海报；开灯路线点两张远端海报揭贴纸，留暗路线在灯灭时再点玻璃，一次凝视读取两张远端编号和留言，最多扣 40 点 SAN。灯可继续切换，已选路线和读数保留。资料柜在四个展位号记齐后开放密码盘。对白仍由共享 `WwgDialogueHost` 呈现，对话期间暂停 SAN 被动消耗。

S0 的傍晚时间推进与 23:30 熄灯在活动室场景中以对白呈现；S1 到达 4F 后直接进入 S2，不显示全屏阶段完成提示。

S2 取得借用便签后，单数栋 4F 入口的 3F 按钮进入 `ServerRoom3F`。S3 草图、归档工具三字段、录音和 U 盘拷贝依次推进；错误索引保留选择且不扣 SAN。首次听录音固定扣 15 SAN，回放不重复扣。拷贝后从机房出口返回 5F 安全屋，并保留路线、P1/P2/P3 进度和任务物品。S3 仍用字幕模拟录音，尚无独立录音音频素材。

S3 拷贝旧工程后从机房出口进入 `FinaleClubRoom`。S4 归档工牌后 SAN 上限升至 120，休息后 SAN 和生命回满。分别与袁祁和许圆复盘，再找唐澈推进到 16:00。选择 `ViewTogether` 后需点击袁祁核对名单、点击许圆核对实物，再点击电脑；选择 `ViewAlone` 一次性扣 10 SAN，需从背包使用 U 盘载入快照，再点击电脑。完成各自的交互才播放相应结尾。四种选择组合均可到达 `24:00:00`。检查点和槽位保留选择、分支操作进度与关键物。`WWG/Setup/Build S4 Finale Room` 只用于首次建立场景。

### 游戏内 UI

S0/S1 的七个地点场景均安装了 `Gameplay overlay`：顶部显示暂停入口、时间、目标、状态和任务记录；底部显示物品栏。ESC 可开关暂停菜单。S1 已取得的旧照片和工牌显示在物品栏，右键或左键打开详情；可选择物品后点击热点，或拖到热点使用。暂停菜单的「存档/读档」与 S2、标题页共用 `SaveSlotPanel`：背景蒙版上直接排列三个存档条，无外层存档框；每条只显示编号、游戏内时间和保存时间。存档条可直接读取，覆盖/删除有确认框。共享 Overlay 的场景安装命令是 `WWG/UI/Install Gameplay Overlay`，已有实例时不会重复创建。

### 编辑与核对

- 场景资源已拆分，日常直接编辑对应地点 `.unity`。`WWG/Build S0 Scene`、`WWG/Build S1 Scene` 和 `WWG/Build Title Scene` 在目标已存在时返回，不覆盖手工资产。
- 后续 `GameRuntime` 重构仍保留这些阶段场景及 S2–S4 独立场景。跨阶段稳定空间逐地点提取基础 Prefab，阶段物件继续在各自 `.unity` 中调整；正式加载将按 `(chapterId, locationId)` 选择对应场景。此条是待实施架构，当前运行仍按上文的章节控制器切屏。
- 一次性拆分命令 `WWG/Setup/Split Location Scenes` 只适用于未拆分的原始 S0/S1；检测到目标场景存在时停止。
- 修改场景流转后从 `Title` 开始 Play，依次点击菜单、楼层展板、大门、活动室、连廊返回、照片、P1、工牌、夜间走廊和 4F 入口。检查 Console，并用包含 Overlay UI 的截图确认按钮和对话框可见。
- 修改对白后执行 `WWG/Yarn/Validate Dialogue`，再在 Play 模式核对说话人、立绘、`show_info` 和一次性冲击。检查点只应在对白结束后的安静点写入。
