# 架构规范

## 已实现层次

```text
TitleMenuController ──▶ WWG.GameFlow ──▶ Unity SceneManager
S0Hotspot ──▶ S0Controller ──▶ WWG.GameFlow
S1Hotspot ──▶ S1Controller ──▶ WWG.GameFlow
                              └─▶ PlayerPrefs 阶段检查点
S1Controller ──▶ S2Controller ──▶ WWG.GameStateStore
                                 └─▶ BridgeOdd4F / BridgeSpan4F / BridgeEven4F / ClubRoom
```

- `GameFlow` 是场景名与加载入口；场景目标必须存在于 Build Settings。主菜单的开始按钮通过 `StartNewGame()` 进入 `S0`。
- `S0Controller` 持有本章调查标记、剧情阶段、对话、HUD 和切屏动作。地点间的状态暂存于静态 `TravelState`，加载新地点后立即恢复；停止 Play 后重置。暂停菜单的手动检查点另用 PlayerPrefs 保存地点与调查标记，仍不是完整 Demo 存档。
- `S1Controller` 持有 P1 三项对位、照片/工牌、SAN/生命及检查点。地点切换使用临时 `Checkpoint` 快照，同时把阶段检查点写入 PlayerPrefs 键 `WWG_S1_Checkpoint`。此机制只覆盖 S1，不能称为完整 Demo 存档。
- `S2Controller` 从 S1 的 4F 终点接收照片、工牌、SAN/生命与 P1 标记；四个地点传递同一 `GameState` 的副本。路线选择与 P2 完成时写入版本化的 `WWG_Save`，但 S0/S1 仍用原章节检查点，尚未形成完整 Demo 存档。
- `SaveSlotStore` 为三个玩家槽位封装 S0/S1 的章节快照或 S2 的 `GameState`；`SaveSlotPanel` 在标题页与暂停菜单复用。首次打开时只复制一份现有最近检查点，不删除旧键。槽位不等同于跨章节完整 Demo 存档。
- 热点组件通过动作字符串调用对应控制器。热点只负责点击、悬停及椅子拖放，不改变全局进度。
- 每个地点场景自含相机、EventSystem、Canvas、控制器和该地点画面；无跨场景对象引用。删除其他画面后，控制器对该地点不存在的画面/热点引用做判空处理。
- `GameplayOverlay` 通过共享预制体实例出现在七个地点场景，负责暂停、物品栏和详情面板；章节控制器仍持有道具、谜题、SAN 与存档状态。`GameplayOverlayBuilder` 只在显式调用安装命令时补齐缺失实例。

## 后续扩展规则

- S3–S4 及 P3 应按 Demo 文档独立规划状态和地点。继续使用 `GameState`，不要复制 S1 的 `PlayerPrefs` 键；完整存档需要覆盖所有章节并恢复到对应地点。
- 两条 4F 调查路线及两种结尾都必须可达。`RouteLight / RouteDark`、`ViewTogether / ViewAlone` 是明确的存档标记，不由低 SAN 随机决定。
- 5F 活动室是安全屋。23:30 只熄公共区域照明；活动室电脑与插座不断电。白天和夜间同一地点的门窗、透视和热点位置保持一致。
- 新的共享 UI 若修改频繁，可在确认所有地点的序列化引用后抽为预制体。当前场景副本是现状，不将预制体复用写成已实现。
- 新增编辑器菜单只能补齐缺失场景或明确另设带确认的覆盖命令；人工维护的 `.unity` 文件不得被域重载或菜单自动重建。
