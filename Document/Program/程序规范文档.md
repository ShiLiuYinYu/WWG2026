# WWG 程序规范文档

> 《熄灯之后：48H》前 24H Demo；以 WJ 的 `Assets/doc/rule/program/` 文档结构为参考，内容以 WWG 的实际资产为准。

## 技术基线

| 项目 | 当前工程 |
| --- | --- |
| Unity | `6000.3.28f1` |
| 渲染 | URP `17.3.0`，2D Renderer |
| 输入 | Input System `1.20.1`，场景 EventSystem 使用 `InputSystemUIInputModule` |
| UI | uGUI `2.0.0`，Screen Space Overlay，1920×1080 参考分辨率 |
| 测试 | Unity Test Framework `1.6.0`；场景交互需进 Play 模式验证 |
| 编辑器桥接 | `com.coplaydev.unity-mcp`；连接前确认实例名称为 WWG |

以 `ProjectSettings/ProjectVersion.txt`、`Packages/manifest.json` 和当前 WWG 编辑器为最终版本依据。

## 项目边界

- 固定视角 2D 点击解谜：场景热点负责调查、道具使用与地点切换。没有自由行走、战斗或追逐。
- 剧本与关卡制作依据 `Document/《熄灯之后：48H》前24H Demo剧本与关卡设计.md`，原始设定见同目录的怪谈文档。设计目标与已实现功能必须分开标记。
- 目前已实现 Title、S0、S1、S2。S1 有 P1、工牌、SAN/生命及阶段检查点；S2 有双栋 P2、`RouteLight / RouteDark`、借用便签、分工表残页和 S2 检查点。S3–S4、P3、第二次选择和完整 Demo 存档仍待制作。
- 低 SAN 残影只提供可核对的真实线索。SAN 或生命耗尽后不得丢失关键道具和谜题进度。
- 不得加入赛事监控、强制汇报或统一上传设定。

## 场景与代码约定

- 一个可点击的固定地点对应一个 `.unity` 场景。地点场景只保留自己的画面与热点；该章节的 HUD、对话框、背包/任务面板及控制器随场景一起保存。
- 场景名与 Build Settings 的对应关系统一放在 `WWG.GameFlow`；UI 按钮不直接调用 `SceneManager`。
- S0/S1 的控制器保存切屏所需状态，再加载目标场景；热点脚本只转发动作，不独立持有谜题进度。章节内临时转场状态不代替持久化检查点。
- 不在场景 A 中序列化引用场景 B 的对象。每个场景只能引用自身对象和项目资源。目标地点的对象字段可为空，代码必须判空。
- 新增场景要登记 Build Settings，并从入口场景实测到达。`SampleScene` 保留为模板，不参与剧情流程。
- 新的关卡状态先定义数据结构与恢复点，再接 UI；关键物品、P1/P2/P3、两次选择和触发过的对话均应进入未来的完整存档。
- 场景画面、热点区域和文字在 Unity 编辑器中维护。旧生成器只负责缺失资产，不覆盖现有场景。`WWG/Setup/Split Location Scenes` 是一次性迁移工具，已有目标地点时拒绝执行。

## 命名与文件

- 文件名和 `MonoBehaviour` 类名一致；公开类型和公开接口使用 PascalCase，私有字段使用 camelCase。避免无意义缩写。
- 当前运行时类分布于 `Assets/Scripts/Core`、`S0`、`S1`、`UI`，编辑器工具在 `Assets/Editor`。现有 S0/S1 类仍处于全局命名空间，新的共享服务使用 `WWG`；迁移命名空间时必须同步检查 Unity 场景脚本引用及按钮回调。
- 暂无自定义 `.asmdef`。新增程序集前先梳理依赖；运行时脚本不得引用编辑器程序集。
- 场景、脚本、图片和音频均提交对应 `.meta`；保留 `Packages/packages-lock.json`。不提交 `Library/`、`Temp/`、`Logs/`、`Obj/`、`UserSettings/` 等生成内容。
- 新文件 UTF-8；C# 使用 4 空格缩进。修改已有文件时尽量维持原有编码与行尾，减少无关差异。

## Git 与验收

- 建议提交格式：`[type](scope): 描述`，例如 `refactor(scene): 拆分 S0 与 S1 地点`。`type` 可用 `feat`、`fix`、`refactor`、`docs`、`test`、`chore`；`scope` 取 `core`、`scene`、`ui`、`editor`、`docs` 等实际模块。
- 改脚本后在 WWG 编辑器执行 `refresh_unity(compile="request", scope="all", wait_for_ready=true)`，检查 Console 错误。改场景/UI 后进入 Play 模式点击真实按钮与热点，截图要包含 Overlay UI。
- 场景流转至少核对 `Title → S0 楼外 → 5F 走廊 → 活动室 → 4F 连廊入口 → 活动室 → S1`；S1 继续验证照片、P1、工牌、夜间走廊、4F 入口及检查点读取。
- 改了场景结构、转场入口或生成菜单时，同步维护本目录文档、根目录 `AGENTS.md` 和 `.opencode/skills/unity-scene-workflow/SKILL.md`。
